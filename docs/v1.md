# Tapgame · Version 1

Three numbers per player, all initially 1, modulo 10. A tap adds the opponent's number to the moving player's number. Zero is withdrawn. Repeating a board of sorted triples for the two named players is forbidden regardless of turn. Clear all three to win, or leave the opponent without a legal tap. A draw is recorded after 20,000 successive taps without a withdrawal. The match referee checks clearing, then timeout, then blocking.

## Run the frozen bot

Build with a C++17 compiler. The supplied model/values.txt table is sufficient for match or move selection.
```sh
g++ -O3 -std=c++17 src/tap.cpp -o tapbot
echo 1112 | ./tapbot choose model/values.txt
./tapbot match 2000 3100000 random model/values.txt > random.csv
./tapbot match 2000 5200000 heuristic model/values.txt > heuristic.csv
```
Each pair of digits in a trace is one tap, moving value first and opponent value second. Empty input selects a move from the opening. The two sample taps in 1112 are 1+1, then 1+2. The bot returns the next tap as two space-separated digits. Seat alternates by game, starting with the bot in seat A. Each game reseeds its own mt19937 generator. The only evaluation-time randomness is the baseline's random selection. Use the same compiler/standard library to replicate randomized ties.

## Reproduce training and the report data

Python 3.12, NumPy 2.3.5 and scikit-learn 1.8.0 were used. Game IDs 0–10799 train the network, and IDs 10800–11999 are held out. Seeds for self-play are 700000–711999. Both evaluation suites use separate seeds and the frozen model. Retraining floating-point results can vary by library or CPU.
```sh
./tapbot features > features.csv
./tapbot train 12000 700000 bootstrap > examples.csv
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python tools/train.py features.csv examples.csv model
python tools/matches.py ./tapbot model/values.txt dist/data
python tools/verify.py
```

The network regresses final outcomes (+1/−1, or 0 on timeout) from the mover's perspective using 26 board features. Each side's ten digit counts, both live counts, move count, withdrawal count, ordinary-game result, and capped ordinary-game solution distance are standardized. Hidden layers have 48 and 24 ReLU units. The frozen leaf score is round(380 × clipped prediction + 180 × ordinary outcome + 25 × (opponent live count − mover live count)). A leaf loses three points for each otherwise possible move blocked by history. Ordinary-game outcomes use backward propagation with infinite play treated as a draw; they are evaluation features only. The model is exported as scores for every ordered pair of 220 sorted triples.

Self-play uses depth-two iterative search limited to 200 main search nodes per move, a hand-crafted bootstrap evaluation, and 18% uniformly random exploration. The deployed evaluation bot searches up to depth eight, with a 4,500-main-node budget per decision. It takes a sole legal move immediately, checks immediate clearance and blocked turns, and solves forced one-against-one lines to termination. Forced-line steps are outside the main-node budget. Its actual game and each search branch track positional superko exactly. Terminal scores outrank all estimates. The deepest completed iteration supplies the move.

Random selects uniformly among distinct legal value pairs. The heuristic first takes an immediate clear or blockade, then prioritizes avoiding an immediate opposing last-number clearance, avoiding any opposing withdrawal next turn, then making its own withdrawal. Equal best moves are chosen uniformly. The independent referee checks every tap, positional history, heuristic choice, termination, outcome and seat assignment.
